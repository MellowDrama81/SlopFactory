# Architecture

## Projects

| Project | Responsibility |
|---|---|
| `Mellow.SlopFactory.Core` | Platform-neutral domain records, validation rules, exceptions, and workspace contracts |
| `Mellow.SlopFactory.Infrastructure` | SQLite persistence, manifests, exclusive locks, hashing, media-type detection, managed file operations, and the workspace implementation |
| `Mellow.SlopFactory.Gui` | .NET MAUI Blazor Hybrid shell and user interface for Windows and Android |
| `Mellow.SlopFactory.Tests` | Cross-platform domain and infrastructure tests running on `net10.0` |

The GUI depends on the application contracts rather than SQLite directly. `LibraryWorkspaceFactory` is registered through dependency injection as `ILibraryWorkspaceFactory`.

## Platform targets

- Windows: `net10.0-windows10.0.19041.0`
- Android: `net10.0-android`, with API level 26 as the minimum supported platform version

The development package identifier is `com.mellow.slopfactory.dev`, keeping development storage separate from a future production identity.

`LibraryLocationService` supplies the platform storage policy. Windows accepts absolute paths on non-network drives. Android enumerates only the process's internal and external app-specific directories. `AppLibraryState` persists the last successfully opened path in device preferences and swaps workspaces only after the replacement library has opened successfully.

The recent-library registry is device-local Preferences JSON, not part of any library. Entries contain the persistent library ID, display name, absolute platform location, stable storage-volume identity, last-opened UTC time, availability state, and only a sanitized open stage/diagnostic ID when corrupt. A successful validated open replaces stale path/name data for that ID. Switching rejects known ancestor/descendant ownership overlaps. If another registered path with the same ID remains available, opening the copy is rejected; if the old path is unavailable, selecting the new path relinks the registry without modifying the library ID. Forgetting removes the registry entry and that ID's preview cache only.

`IncomingImportService` bridges platform activation into Blazor without importing implicitly. Android `SEND`/`SEND_MULTIPLE` intents copy read-only content streams into a private random cache directory immediately, then release the provider grant. Windows file activation and native WebView drag/drop enqueue validated regular local paths; dropped directory enumeration is capped at 64 levels and 100,000 files and excludes hidden or reparse-point entries. Each dropped file carries a relative folder path, which the confirmed operation resolves into existing or newly created virtual folders below the reviewed destination. The memory queue survives page navigation, exposes a global review banner, and reports sanitized provider/enumeration failures. The Library page drains it into the ordinary import review. Temporary shared copies are deleted on removal, review cancellation, or completion; orphan staging directories from a terminated process are deleted on the next service startup.

## Library workspace lifecycle

`ILibraryWorkspaceFactory.CreateAsync` initializes an empty directory. `OpenAsync` accepts only a manifest/database pair with matching identity and schema information. Both return an `ILibraryWorkspace`, which owns an exclusive lock for its lifetime and must be asynchronously disposed.

Opening validates that the root, manifest, database, managed-media directory, and staging directory are the required regular entry types and are not reparse-point redirections. The root is checked before manifest access, required entries are checked before locking/database work, and managed directories are checked again after obtaining the exclusive lock. Individual managed-path access also rejects directories and reparse points.

The workspace is the atomic application boundary for folder browsing, imports, file and folder rename/move operations, bounded text and verified image reads, edited-copy commits, metadata, link creation/relabel/reversal, recycle/restore, and permanent file deletion. Multi-file move, recycle, metadata-set, and metadata-remove calls hold this boundary for the complete batch, while each selected file uses its own database transaction and produces an independent sanitized outcome. Invalid or duplicate selections are rejected before processing. Folder moves validate the complete descendant chain before updating the parent identifier; display-only organization never changes a file's internal managed name or byte location.

The built-in text reader accepts strict UTF-8 with or without its byte-order mark. Invalid UTF-8 and UTF-16 byte-order marks are rejected with a user-facing validation error. UI display is capped at 1,048,576 characters as a memory-safety boundary, not as a library storage limit.

The inline raster reader accepts PNG, JPEG, WebP, and GIF records up to 32 MiB. It reads only an active managed file and verifies its byte count and SHA-256 digest against the database before returning bytes to the WebView. The size boundary limits transient base64 and WebView memory; it is not a library storage quota.

SVG uses the same raw-byte verification before a strict XML sanitizer creates the viewing representation. DTDs and external XML resolution are prohibited. A small allowlist retains passive SVG geometry, text, definitions, gradients, masks, patterns, markers, symbols, and local fragment reuse; active elements, foreign namespaces, event attributes, style attributes, external links, and external CSS URLs are removed. The unsanitized SVG is never sent to the WebView.

Audio/video playback is capability-scoped rather than path-based. The workspace first validates an active playable record, a regular non-reparse managed file, byte size, and complete SHA-256 digest. The GUI then creates a random 256-bit session grant and gives HTML media controls only a same-origin `/slopfactory-media/<token>` address. `BlazorWebView.WebResourceRequested` intercepts that address, accepts only `GET` and `HEAD`, implements one bounded HTTP byte range with `200`, `206`, or `416` semantics, and opens a non-seekable length-limited stream. It returns `nosniff` and `no-store` headers and never discloses a managed path. Grants are bound to a library ID and content hash and are revoked when the component reloads or is disposed. JavaScript coordinates one active player, playback rate, and teardown; no media is autoplayed.

Raster viewing also performs header-level safety validation before WebView decode: dimensions are capped at 16,384 per axis and 100 million total pixels, while GIF frame count and estimated decoded animation memory are bounded. Exceeding a limit rejects only the preview and does not change the record or bytes.
Animated GIFs use the cached static thumbnail as their initial and paused representation. The original animated data URI is not attached to the DOM until the user explicitly plays it, and navigation restores the paused representation.

`PreviewCacheService` stores PNG thumbnails outside libraries under MAUI's device cache directory. Cache identities hash library ID, content hash, preview type, target size, and renderer version. Two workers generate previews on demand; raster images use MAUI Graphics and MP4 posters use `StorageFile` thumbnails on Windows or `MediaMetadataRetriever` on Android. A cache hit advances its filesystem LRU time. A device-wide 64 MiBâ€“8 GiB preference defaults to 1 GiB on Windows and 256 MiB on Android; writes and limit changes evict oldest entries. Cache status and explicit clearing are exposed in Library settings. Cache files contain no authoritative data and can disappear normally.

`ManagedContentWatchService` watches only the active library's top-level managed-media directory. It restarts on library switches, debounces per opaque managed filename, ignores paths without active records, and routes known records through workspace revalidation. Healthy expected import/copy events clear silently; missing or changed results become global review notices. An overflow or inaccessible revalidation produces only a full-scan recommendation. The watcher is advisory and never follows directories, accepts bytes, deletes content, or replaces the explicit verification performed by viewers and integrity scans.

The watcher also performs a low-frequency availability probe using the remembered stable volume identity and required writable atomic operations. An unavailable or read-only active library is detached safely while its registry entry remains. An entry closed specifically for unavailable Android storage is reopened only after the same volume and library validate again; corrupt entries are never auto-repaired or auto-opened.

The same service uses a separate root watcher for the manifest and primary SQLite file. Each critical event invokes `ValidateOpenLibraryAsync`, which acquires the workspace mutation gate, revalidates required entries, exact in-memory manifest and descriptor identity, and SQLite integrity. Failure asks `AppLibraryState` to atomically detach and dispose only that expected workspace while retaining its path and an actionable unavailable-library message. A stale watcher callback cannot close a subsequently selected library.

## Connections, models, and provider adapters

`Connection` and `Model` are library-scoped domain records (schema v9) exposed through `ILibraryWorkspace`, following the same active/recycled/pending-permanent-deletion lifecycle, label-uniqueness, and cascade conventions as folders and files: recycling a connection recycles its dependent models, and permanently deleting a connection permanently deletes those models. A connection's base URL is validated and normalized by `LibraryRules.NormalizeConnectionBaseUrl` (absolute `http`/`https`, no embedded credentials, HTTPS required for public hosts, HTTP allowed only for loopback/private-network hosts).

`IProviderAdapter` (Core/Application) defines `TestConnectionAsync` and `ListModelsAsync`. `OpenAiProviderAdapter` and `GenericOpenAiCompatibleProviderAdapter` (Infrastructure/Providers) implement it over a typed `HttpClient`, sharing request/response handling through `OpenAiCompatibleProtocol`. `IProviderAdapterResolver` resolves the adapter for a connection's `ProviderType` and is registered, along with the two adapters, by `AddSlopFactoryInfrastructure()`.

API keys are never stored in the library database. The GUI's `ISecureCredentialStore` (`MauiSecureCredentialStore`) wraps MAUI `SecureStorage`, keyed by library ID and connection ID; the `Connection` record only stores a `HasCredential` flag. The Connections and Models pages (`Components/Pages/Connections.razor`, `ConnectionEdit.razor`, `Models.razor`, `ModelEdit.razor`) call the resolved adapter directly for **Test Connection** and **Load Models**, and remove the stored credential when a connection is permanently deleted.

This is an initial slice of Milestone 2's connections-and-models scope; the remaining credential-lifecycle, capability-schema, and generation-workflow behavior is tracked in [milestone2.md](../../milestone2.md).

`ConnectionEdit.razor`'s `IsInsecureHttpBaseUrl` parses `_form.BaseUrl` live (independent of the save-time `LibraryRules` validation) and shows a warning the moment its scheme is `http`, since by the time an `http://` base URL is actually persisted, `NormalizeConnectionBaseUrl` has already guaranteed it is loopback/private-only — the warning exists purely so the user understands *why* before hitting save. `Connections.razor` shows the same warning as a short badge next to any already-saved connection whose stored `BaseUrl` starts with `http://`.

## Minimal text generation

`GenerationRecord` (schema v10: `generation_records`/`generation_results`) is a lightweight, synchronous generation-history record reached through `ILibraryWorkspace.RecordTextGenerationResultAsync`. It has none of the plan's full generation-lifecycle machinery (no drafts/tabs, queue, cancellation, retries, or async job polling) — it exists to let the `/generate` page turn a prompt into library content end to end.

`IProviderAdapter.GenerateTextAsync` requests one or more chat-completion candidates (`OpenAiCompatibleProtocol.BuildChatCompletionRequestBody`/`ParseChatCompletionTexts`) from the OpenAI or generic adapter. The `/generate` page calls it directly, then calls `RecordTextGenerationResultAsync` with either the returned texts or a sanitized error message. `LibraryWorkspace.RecordTextGenerationResultCoreAsync` commits each text candidate as its own managed `.md` file (`FileOrigin.Generated`) using the same staging-write, hash, atomic-move sequence as `CreateEditedTextCopyAsync`, then records one `generation_records` row (model/provider snapshot, prompt, status, sanitized error) linked to its committed files through `generation_results`. A failed attempt (adapter threw) still commits a `Failed` history row with no files. `/generation-history` lists these records newest first.

`IProviderAdapter.GenerateImageAsync` requests base64-encoded image results (`OpenAiCompatibleProtocol.BuildImageGenerationRequestBody`/`ParseImageGenerationBytes`, POST `images/generations`, `response_format: b64_json`) and returns decoded byte arrays. `RecordImageGenerationResultCoreAsync` mirrors the text path but writes each image's bytes to staging first and detects its real media type/extension with `MediaTypeDetector.DetectAsync` (the same file-signature detector import uses) rather than trusting the provider's declared format, before the same atomic move and `InsertImportedFileAsync` commit. The `/generate` page offers one combined, mode-labelled model picker and branches to the text or image path based on the selected model's `GenerationMode`.

Everything else under Generation Inputs/Lifecycle/Results/History in `plan.md` — source inputs, prompt improvement, queues, audio/video results, provider result download/validation (status/content-type/checksum, unverified-binary retention), and recycle-bin integration — remains open, tracked in [milestone2.md](../../milestone2.md).

## Saved generation settings

`SavedGenerationSetting` (schema v11: `saved_generation_settings`) is a title, model snapshot (ID plus label/mode, so a later-unavailable model still shows something meaningful), prompt, result count and destination folder, reached through `ILibraryWorkspace`'s saved-setting CRUD. It follows the same active/recycled/pending-permanent-deletion lifecycle and title-uniqueness convention as connections and models, and the same cascade shape: recycling a model recycles its dependent saved settings (and restoring/permanently deleting the model does the same in reverse), and recycling/restoring/permanently deleting a connection cascades through its models to their saved settings.

The `/generate` page (routed at both `/generate` and `/generate/{SettingsId}`) loads a saved setting's prompt/result-count/destination/model into its form when opened with an ID, and offers **Save settings**: entering a title and saving updates the same record only when the loaded title is unchanged, and creates a new one otherwise (there is no true **Save**/**Save As** revision-conflict review yet). `/saved-settings` lists active and recycled saved settings with **Use** (opens `/generate/{id}`), recycle, restore and permanent delete.

A third route, `/generate/history/{HistoryId}`, backs a minimal **Use Again**: it loads a historical `GenerationRecord`'s prompt/result-count/destination/model into the same form without treating it as a saved setting (it never sets the loaded-settings/title state that makes **Save settings** update in place) and without altering the historical record itself. `/generation-history` links each entry to it.

## System instructions

Text-mode generation carries an optional **System Instructions** field (schema v12: `generation_records.system_instructions`, `saved_generation_settings.system_instructions`), shown on `/generate` only when the selected model's `GenerationMode` is `Text`. `OpenAiCompatibleProtocol.BuildChatCompletionRequestBody` writes it as the first message with the documented `system` role — never concatenated into the user prompt — and both adapters' `GenerateTextAsync` accept it as an optional parameter. It flows through `RecordTextGenerationResultAsync`, `CreateSavedSettingAsync`/`UpdateSavedSettingAsync`, saved-setting loading and **Use Again** the same way the prompt does; image generation never receives it. `/generation-history` shows it behind a collapsed `<details>` disclosure per record — a minimal stand-in for the documented reveal-and-clear-on-navigation behavior, not the full privacy mechanism.

## Token usage

`IProviderAdapter.GenerateTextAsync` returns a `TextGenerationResult` (texts plus optional `PromptTokens`/`CompletionTokens`) instead of a plain string list. `OpenAiCompatibleProtocol.ParseChatCompletionResult` reads the OpenAI-shaped `usage.prompt_tokens`/`usage.completion_tokens` fields when the provider includes them. `GenerationRecord` persists them (schema v13: `generation_records.prompt_tokens`/`completion_tokens`); `/generate`'s result panel and `/generation-history` show them when known. Only text generation captures usage this way — image generation, cost estimation and a cost-summary view remain open.

## Vision source image

`/generate` offers one optional source image (from the active library's image-media files) when the selected model is Text-mode. `LibraryState`'s workspace reads it through the existing `ReadImageFileAsync` verified-read pipeline (hash-checked, same as the file viewer) rather than a raw path, and passes the bytes/media type to `IProviderAdapter.GenerateTextAsync` as an optional `TextGenerationSourceImage`. `OpenAiCompatibleProtocol.BuildChatCompletionRequestBody` switches the user message from a plain string to a `[{type:"text"},{type:"image_url", image_url:{url:"data:<mediaType>;base64,..."}}]` array when an image is supplied — the OpenAI vision content-part shape, supported by both adapters. The referenced file ID is persisted on `GenerationRecord`/`SavedGenerationSetting` (schema v14: `source_file_id`, `ON DELETE SET NULL` so a later permanent file deletion clears the reference rather than leaving it dangling) and carried through **Save settings** and **Use Again**. Image-mode generation and multi-source/named-slot input remain open.

## Cancellation

`/generate`'s **Generate** action creates a `CancellationTokenSource` passed to the adapter call, the result commit and the history insert. Clicking **Cancel** (shown only while busy) requests cancellation; if it unwinds before `RecordTextGenerationResultAsync`/`RecordImageGenerationResultAsync` runs, no `GenerationRecord` is created at all — the page shows a message that the provider may still process or charge for an already-sent request rather than guessing a terminal status. This deliberately does not implement the documented `Submission Outcome Unknown` state, per-stage cancellation semantics (before-submission vs. mid-upload vs. already-accepted), or reconciliation.

## Generation history filters

`/generation-history` filters its already-loaded list client-side by status, mode and model label (each an independent `<select>` bound to a plain string field, `""` meaning no filter) via a computed `FilteredRecords` property, plus a **Clear filters** action. There is no date/provider filter, no server-side query, and no persistence of the filter selection across navigation.

## Connection credential and verification status

`Connections.razor`'s `StatusLabel` checks `Connection.HasCredential` before `LastTestStatus`, so a connection with no stored API key always shows **Credentials Required** rather than **Unverified**/**Test Failed**, even if it happens to carry a stale successful `LastTestStatus` from before a credential was removed. `/generate` mirrors this through a computed `SelectedConnection` property: `!SelectedConnection.HasCredential` disables the **Generate** submit button and shows a blocking notice linking to `/connections/{id}`, while `SelectedConnection.IsUnverified` (any status other than `Success`) shows a non-blocking warning instead; `GenerateAsync` and `ImprovePromptAsync` both re-check `HasCredential` server-side (in-process) before calling the adapter, since the UI guard alone is not authoritative. `SqliteLibraryDatabase.UpdateConnectionAsync` already unconditionally resets `LastTestStatus` to `Untested` on every edit, so retesting-after-edit is already enforced; what remains open is a **Secure Storage Unavailable** state (credential store itself failing versus the credential being absent), an **Authentication Failed** state derived from inspecting a connection-wide `401` rather than a generic failed test, and collapsing the unverified warning into a one-time per-revision confirmation instead of showing it on every use.

## Connection timeout override

`Connection.TimeoutSeconds` (schema v16, nullable) is validated by `LibraryRules.NormalizeConnectionTimeoutSeconds` against a shared 5–600 second range (`MinimumConnectionTimeoutSeconds`/`MaximumConnectionTimeoutSeconds`); `null` means the application default, `LibraryRules.DefaultConnectionTimeoutSeconds` (100 seconds — chosen to match `HttpClient`'s prior default so unconfigured connections behave exactly as before). `ConnectionEdit.razor` exposes it as an `InputNumber` under **Advanced connection settings** and threads the candidate value into the probe `Connection` built for **Test Connection**, so a not-yet-saved timeout value is exercised before the user commits it.

All four `IProviderAdapter` HTTP calls (`TestConnectionAsync` delegates to `ListModelsAsync`) now go through `OpenAiCompatibleProtocol.SendAsync(httpClient, request, connection, cancellationToken)`, which creates a `CancellationTokenSource` for `connection.TimeoutSeconds ?? DefaultConnectionTimeoutSeconds` seconds, links it with the caller's `cancellationToken`, and sends/reads the response on the linked token. A `catch (OperationCanceledException) when (timeoutCts.IsCancellationRequested && !cancellationToken.IsCancellationRequested)` clause converts a timeout specifically into `ProviderAdapterException($"The request timed out after {timeoutSeconds} seconds.")`, while a real caller-driven cancellation (the external token itself cancelled) still propagates as `OperationCanceledException`/`TaskCanceledException` unchanged. This closes a latent bug: previously each adapter method called `_httpClient.SendAsync` directly against the shared typed `HttpClient`'s own (default ~100s) `Timeout`, which throws a bare `TaskCanceledException` indistinguishable from user cancellation — on `/generate`, `GenerateAsync`'s `catch (OperationCanceledException)` block would have reported a slow provider as "Generation cancelled by the user" instead of a provider timeout. `DependencyInjection.AddSlopFactoryInfrastructure` now sets each adapter's injected `HttpClient.Timeout` to `Timeout.InfiniteTimeSpan` so `SendAsync`'s linked-token logic is the only timeout enforcement in play. Both adapters' `TestConnectionAsync` methods dropped their now-dead `catch (TaskCanceledException) when (!cancellationToken.IsCancellationRequested)` clause, since a timeout now always surfaces as `ProviderAdapterException`, already handled by an existing catch clause there.

## Additional connection headers

`Connection.AdditionalHeaders` (schema v17, `connection_headers` child table keyed by `(connection_id, name)`) holds plain `ConnectionHeader(Name, Value)` pairs for gateway/routing use cases (an organization header, a routing key, an API version pin) — explicitly non-secret by construction. `LibraryRules.NormalizeConnectionHeaders(headers, credentialHeaderName)` caps the list at 10 entries and 500 characters per value, rejects duplicate names (case-insensitive), and refuses both standard transport/hop-by-hop headers (`Host`, `Content-Length`, `Connection`, `Transfer-Encoding`, etc.) and anything that would otherwise carry a credential (`Authorization`, `Proxy-Authorization`, `Cookie`/`Set-Cookie`, or the connection's own configured credential header name) — those are refused outright rather than accepted and stored as plaintext, since secret-header handling would need the same secure-storage-backed candidate/promotion machinery as the primary API key, which does not exist. `SqliteLibraryDatabase.ReplaceConnectionHeadersAsync` deletes and reinserts the full set inside the same transaction as the connection row update, so header changes are atomic with everything else `CreateConnectionAsync`/`UpdateConnectionAsync` writes; `GetConnectionAsync`/`ListConnectionsAsync` load headers via a second query per connection immediately after the row read (SQLite/`Microsoft.Data.Sqlite` has no MARS, so a second reader on the same connection cannot be open concurrently with the first). `ConnectionEdit.razor` renders/parses them as a `Name: Value`-per-line textarea (`FormatHeaderLines`/`ParseHeaderLines`), reusing the same `LibraryRules.NormalizeConnectionHeaders` validation for both the **Test Connection** probe and **Save**. `OpenAiCompatibleProtocol.ApplyAdditionalHeaders` applies them via `TryAddWithoutValidation` on every adapter request, right after `ApplyAuthorization`.

## Connection provider-type change

A connection's provider type can only change when it has zero *active* dependent models. `ILibraryWorkspace.ChangeConnectionProviderTypeAsync` is intentionally a separate method from `UpdateConnectionAsync` — inserting a `providerType` parameter into the existing signature would have meant a positional-argument break across every call site, whereas a dedicated method needed no changes to `CreateConnectionAsync`/`UpdateConnectionAsync` at all. It validates the connection is active, counts `models WHERE connection_id=$id AND state=0` and throws `LibraryValidationException` if that count is non-zero, then resets `GenericModalitySettings` to `GenericConnectionModalitySettings.Default` (since generic per-modality settings are meaningless once the provider type is no longer `GenericOpenAiCompatible`, and stale settings should not silently persist into a future switch back) and resets the test status to `Untested` like every other connection edit. `ConnectionEdit.razor` computes `_hasDependentModels` once in `OnInitializedAsync` (`GetActiveModelsAsync().Any(model => model.ConnectionId == Id)`) and disables the provider-type `<InputSelect>` only when true; on save, if the selected provider type differs from `_originalProviderType`, it calls `ChangeConnectionProviderTypeAsync` after the main `CreateConnectionAsync`/`UpdateConnectionAsync` call so the reset-to-default modality settings are the final write, regardless of whatever stale values remained in the (now-hidden) per-modality form fields.

Connection-label-change independence from dependent models required no code change: `Model` stores only `ConnectionId`, never a cached copy of the connection's label, so every page resolves the current label by looking up the connection fresh each render. This is exercised by the existing `UpdatingAConnectionResetsItsTestStatusWithoutAffectingDependentModels` test.

## Generic connection per-modality settings

`Connection.GenericModalitySettings` (schema v18, six columns on `connections`: an enabled flag and an optional relative-path override for each of models/text-generation/image-generation) is meaningful only for `ProviderType.GenericOpenAiCompatible` — `OpenAiProviderAdapter` never reads it, since the dedicated OpenAI adapter always uses fixed, documented paths. `LibraryRules.NormalizeGenericModalitySettings` defaults a `null` settings value to `GenericConnectionModalitySettings.Default` (all three modalities enabled, no path overrides) and validates each configured path through `NormalizeRelativePathOverride`, which rejects an absolute URL or a `..` segment; a structural scheme/host takeover is impossible regardless, because `OpenAiCompatibleProtocol.CombineUrl` builds the final URL by string-concatenating the override onto the connection's own base URL rather than parsing it as an independent URI. `GenericOpenAiCompatibleProviderAdapter`'s three HTTP-calling methods each read `connection.GenericModalitySettings?.<Path>Override ?? "<default-path>"` and check the corresponding `...Enabled` flag first, throwing `ProviderAdapterException` before constructing any `HttpRequestMessage` when a modality is disabled. `ConnectionEdit.razor` renders the three enabled/path-override rows only when `_form.ProviderType == ProviderType.GenericOpenAiCompatible`, alongside a computed (client-side string-concatenation, not a live network probe) resolved-endpoint preview per modality.

## Model catalogue caching

Each connection persists its latest discovered-model catalogue (schema v15: `connections.catalogue_retrieved_at`/`catalogue_possibly_stale` plus a `connection_model_catalogue` table of `(connection_id, provider_model_id, display_label)`, replaced wholesale on every refresh). `ILibraryWorkspace.GetModelCatalogueAsync` reads it; `RefreshModelCatalogueAsync` replaces the cached entries and sets the retrieval timestamp while clearing the possibly-stale flag; `MarkModelCatalogueRefreshFailedAsync` sets the possibly-stale flag without touching the retained entries or timestamp. `ModelEdit.razor`'s **Load Models** action calls the adapter directly for its own discovery dropdown (`_discoveredModels`, unchanged) and separately persists the same result into the cache — a successful call refreshes it, a failed one marks it possibly stale — then displays the cache's retrieval timestamp/age plus a **Possibly Stale** (immediate, from a failed refresh) or **Stale** (`DateTimeOffset.UtcNow - RetrievedAt > LibraryRules.ModelCatalogueStalenessPeriod`, 7 days) label. `Models.razor` loads each distinct connection's catalogue once per page load and marks a configured model **Not Currently Listed** when its `ProviderModelId` is absent from that connection's cached entries and a catalogue has actually been retrieved (`RetrievedAt is not null`) — a connection with no catalogue yet renders no judgment either way. None of this ever triggers a network request, deletes, or disables a configured model; it is a passive label only. The catalogue is refreshed solely through the explicit **Load Models** action — not automatically during initial connection setup or connection retesting — and there is no per-adapter override of the 7-day staleness period.

## Per-model system-instructions capability

`Model.SupportsSystemInstructions` (set in `ModelEdit.razor`, persisted by `SqliteLibraryDatabase.CreateModelAsync`/`UpdateModelAsync`) now gates behavior on `/generate` rather than existing only as a stored flag. A computed `SelectedModel` property replaces the model lookup previously duplicated across `SelectedModelMode`, and the System Instructions field renders only when `SelectedModel?.SupportsSystemInstructions == true` for a Text-mode model — otherwise a note explains why the field is absent. `GenerateAsync` and `SaveSettingsAsync` both check `model.SupportsSystemInstructions`/`SelectedModel?.SupportsSystemInstructions` directly before including `_form.SystemInstructions`, so switching from a capable model to an incapable one and generating without revisiting the (now-hidden) field cannot leak a stale value into the request or a saved setting. The generic adapter still does not inspect provider responses for signs a `system` role was rejected, so there is no confirmation flow that offers to flip the flag automatically after a provider-side rejection.

## Prompt improvement

`/generate` offers an **Improve Prompt** panel, shown whenever at least one active Text-mode model exists. The user picks an improvement model (any active Text-mode model, independent of the output model) and may supply free-text guidance; `ImprovePromptAsync` calls `IProviderAdapter.GenerateTextAsync` against the improvement model, passing the current prompt as the user message and a fixed, versioned instruction string (`PromptImprovementTemplate`, formatted with the output model's mode) through the existing `system`-instructions parameter rather than inventing a second channel. The returned `TextGenerationResult.Texts` are shown as candidates the user can individually accept into the prompt textarea (`UseImprovedPrompt`) or ignore; nothing is written until a candidate is chosen. This is a purely in-session helper — there is no raw-vs-improved persistence on `GenerationRecord`/`SavedGenerationSetting`, no **Include Target Model Identity**/**Include System Instructions in Improvement**/**Include Compatible Sources** opt-ins, no **View Instruction** display, and no candidate size bounds or **Refused**/**Unsupported Response**/**Interrupted**/**Needs Review** handling.
